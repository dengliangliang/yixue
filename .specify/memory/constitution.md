# 1213易学算命小程序 - 项目宪法

> 本文档定义项目的核心架构约束、技术规范和开发原则。所有代码变更必须遵守这些规则。

## 1. 项目概述

### 1.1 项目定位
- **项目名称**: 1213易学算命小程序
- **业务领域**: 易学命理测算服务
- **核心功能**: 四柱八字排盘、起运计算、五行分析
- **目标用户**: 需要命理测算服务的C端用户

### 1.2 技术架构
- **后端框架**: ThinkPHP 5.1 + FastAdmin
- **前端框架**: uni-app (Vue 2)
- **数据库**: MySQL 5.7
- **部署环境**: 
  - 开发环境: Windows
  - 生产环境: Linux (47.104.249.160)
- **第三方库**: 
  - lunar-php (农历日期转换)
  - EasyWeChat (微信集成)

## 2. 数据库操作规范

### 2.1 强制约束

#### 2.1.1 参数化查询
**必须使用** `prepareParam()` 方法进行参数绑定，禁止直接拼接SQL：

```php
// ✅ 正确
$result = Db::name('user')
    ->where('id', ':id')
    ->bind(['id' => $userId])
    ->find();

// 或使用 prepareParam
$params = Db::prepareParam([':id' => $userId]);
$result = Db::query("SELECT * FROM fa_user WHERE id = :id", $params);

// ❌ 错误 - 禁止SQL注入风险
$result = Db::query("SELECT * FROM fa_user WHERE id = {$userId}");
```

#### 2.1.2 事务管理
事务方法必须使用**静态调用**：

```php
// ✅ 正确
Db::startTrans();
try {
    // 业务逻辑
    Db::commit();
} catch (\Throwable $e) {
    Db::rollback();
    throw $e;
}

// ❌ 错误 - 不要使用实例方法
$db = Db::instance();
$db->startTrans(); // 错误
```

#### 2.1.3 异常捕获
必须捕获 `\Throwable` 而非 `Exception`：

```php
// ✅ 正确
try {
    // 代码
} catch (\Throwable $e) {
    // 处理
}

// ❌ 错误
catch (Exception $e) { } // 不完整
```

### 2.2 数据库表前缀
- 统一使用 `fa_` 前缀
- 使用 `Db::name()` 自动添加前缀
- 禁止硬编码表名

## 3. 前端开发规范

### 3.1 uni-app 小程序约束

#### 3.1.1 样式选择器限制
小程序**仅支持 class 选择器**：

```css
/* ✅ 正确 */
.user-info { }
.btn-primary { }

/* ❌ 错误 - 小程序不支持 */
* { } /* 通配符 */
p { } /* 标签选择器 */
#header { } /* ID选择器（性能差）*/
```

#### 3.1.2 禁止使用的HTML标签
小程序不支持以下标签的样式选择器：
- `<p>` 标签选择器
- 任何原生HTML标签选择器

### 3.2 API请求规范
- 统一使用 `@/common/request/api.js` 封装的方法
- Token 自动从 `uni.getStorageSync('token')` 获取
- 错误码 401 自动跳转登录页

### 4.2 命名规范
- **PHP类名**: 大驼峰 (PascalCase)
- **PHP方法名**: 小驼峰 (camelCase)
- **数据库字段**: 下划线分隔 (snake_case)
- **前端组件**: 大驼峰 (PascalCase)
- **前端方法**: 小驼峰 (camelCase)

## 5. 业务逻辑约束

### 5.1 农历日期处理
- 使用 `lunar-php` 库进行公历农历转换
- 闰月表示: 负数月份 (如 `-4` 表示闰四月)
- 时辰计算必须考虑真太阳时修正

### 5.2 四柱八字计算
- 日干作为参照点（日元）
- 十神关系基于五行生克
- 五行强弱判断遵循既定算法（见知识库）

### 5.3 数据完整性
- 测算记录必须关联用户ID
- 删除记录时需同步删除关联的 `record_shen` 数据
- 禁止物理删除用户数据（使用软删除）

## 6. 安全规范

### 6.1 认证授权
- API接口默认需要登录验证
- 使用 `$noNeedLogin` 数组声明无需登录的接口
- Token 验证失败返回 401 状态码

### 6.2 数据验证
- 所有用户输入必须验证
- 手机号格式: `^1\d{10}$`
- 禁止信任客户端传入的用户ID

### 6.3 敏感信息
- 数据库密码不得硬编码
- 使用环境变量或配置文件管理
- API密钥统一管理

## 附录：关键技术决策

### ADR-001: 为什么使用 lunar-php
- **决策**: 使用 `6tail/lunar-php` 进行农历计算
- **原因**: 
  - 支持完整的农历日期转换
  - 提供八字排盘功能
  - 维护活跃，兼容性好
- **影响**: 依赖第三方库，需关注版本更新

### ADR-002: 为什么使用 prepareParam
- **决策**: 强制使用参数化查询
- **原因**: 
  - 项目自定义数据库类不支持标准PDO绑定
  - 防止SQL注入
  - 统一代码风格
- **影响**: 所有数据库查询必须遵循此规范
